\section{Little Girl and Maximum Sum (Codeforces 276C)}
\textbf{Problem.} An array $A[1,n]$ and a set $Q$ of $m$ queries, each a $\textsf{RangeSum}(i,j)$. \hlb{Permute the values of \mbox{$A$} to maximize the total of the answers of the queries.}

\noindent\textbf{Example} (your notes). $A=[5,2,4,1,3]$, total $15$; with the queries $(1,5),(2,3),(2,3)$ the value is $15+(2+4)+(2+4)=27$;
with $A_\pi=[2,5,4,1,3]$ it is $15+(5+4)+(5+4)=33$.
\extra{} Your notes write the queries as $(1,5),(1,2),(1,2)$, but the sums $2+4$ and the frequencies $1,3,3,1,1$ correspond to $(2,3)$: I used $(2,3)$.

\noindent\textbf{Idea.} \hlb{Put the largest values in the positions touched by most queries.}
\begin{enumerate}[nosep]
\item \textbf{Count the frequency of every position} (how many queries contain it). Example: $F=[1,3,3,1,1]$; assigning $5,4$ to the two positions of frequency $3$ gives $33$.
  \begin{itemize}[nosep]
  \item with a sweep line (your notes: $\Theta(n\log m)$);
  \item \hlg{with prefix sums}: build an array $B$ whose prefix sums are $F$: \hly{every query \mbox{$(i,j)$} adds \mbox{$+1$} at \mbox{$i$} and \mbox{$-1$} at \mbox{$j+1$}}
        (``the position after the end of a segment contributes $-1$''). Example: $Q=(2,4),(1,3),(2,5)$ $\Rightarrow$ $B=[1,2,0,-1,-1]$, prefix sums $F=[1,3,3,2,1]$.
        \hlg{\mbox{$\Theta(n+m)$}.} Equivalently two counting arrays, $C_{\text{begins}}=[1,2,0,0,0]$ and $C_{\text{ends}}=[0,0,1,1,1]$: $B$ is their combination.
  \end{itemize}
\item \textbf{Sort} $A$ in decreasing order and the positions by decreasing frequency, and assign the largest value to the most frequent position.
\end{enumerate}
Your notes give the total time as $\Theta(n\log n+m\log m)$. \extra{} With the $B$ array the frequencies cost $\Theta(n+m)$ and only the two sorts of $n$ values remain:
$\Theta(n\log n+m)$ (the $m\log m$ belongs to a version that sorts the queries).

\noindent\textbf{Prof's code} [blog] (verbatim):
\begin{lstlisting}
// We assumes queries are 0-based indexed
pub fn little_girl(a: &[i64], q: &[(usize, usize)]) -> i64 {
    if a.is_empty() {
        return 0;
    }

    let mut u = vec![0i64; a.len()];

    for &(l, r) in q {
        assert!(l <= r);
        assert!(r < u.len());

        u[l] += 1;
        if r + 1 < u.len() {
            u[r + 1] -= 1;
        }
    }

    let mut f = u
        .iter()
        .scan(0, |sum, e| {
            *sum += e;
            Some(*sum)
        })
        .collect::<Vec<_>>();

    // we sort both f and a in decreasing order, nothing changes
    f.sort_unstable();
    let mut a_sorted = a.to_vec();
    a_sorted.sort_unstable();

    a_sorted
        .iter()
        .zip(f)
        .fold(0, |result, (value, freq)| result + value * freq)
}
\end{lstlisting}
\noindent\extra{} It sorts both in \emph{increasing} order: pairing the $k$-th smallest with the $k$-th smallest is the same as pairing the largest with the largest.

\section{Number of Ways (Codeforces 466C)}
\emph{(``Problem \#3'' in your notes; problem \#2 is not in your notes.)}

\noindent\textbf{Problem.} Given $A[1,n]$, count \hlb{in how many ways we can split \mbox{$A$} into 3 (non-empty, contiguous) parts with the same sum}. Example: $A=[1,2,3,0,3]$
(answer $2$: $[1,2\,|\,3\,|\,0,3]$ and $[1,2\,|\,3,0\,|\,3]$ \extra).

\noindent\textbf{Idea} (your notes). $S$ = sum of $A$, target $T=S/3$ (if $3\nmid S$ the answer is $0$ \extra).
\begin{itemize}[nosep]
\item Scan left to right computing prefix sums and \hly{mark with ``+'' every position where the prefix sum is \mbox{$T$}} (end of a valid first part).
\item Scan right to left and \hly{mark ``red'' every position where the suffix sum is \mbox{$T$}} (start of a valid third part).
\item \hlb{Answer = number of pairs (``+'', red) with the red point to the right of the ``+''} (leaving a non-empty middle part). For each ``+'', the number of red points to its right
      is a \hly{suffix sum on the red marks}: precompute it and the whole thing is \hlg{linear}.
\end{itemize}
\extra{} Why the middle part is fine automatically: if the first part sums to $T$ and the last to $T$, the middle sums to $S-2T=T$.

\noindent\textbf{Prof's code} [blog] (verbatim):
\begin{lstlisting}
pub fn number_of_ways(a: &[i64]) -> usize {
    let sum: i64 = a.iter().sum();

    if sum % 3 != 0 {
        return 0;
    }

    let target = sum / 3;
    let mut c: Vec<_> = a
        .iter()
        .rev()
        .scan(0, |sum, e| {
            *sum += e;
            Some(*sum)
        })
        .scan(0, |counter, sum| {
            if sum == target {
                *counter += 1usize
            };
            Some(*counter)
        })
        .collect();

    c.reverse();

    let mut result = 0;
    let mut sum = 0;
    for (i, &v) in a[..a.len() - 2].iter().enumerate() {
        sum += v;
        if sum == target {
            result += c[i + 2];
        }
    }

    result
}
\end{lstlisting}
\noindent\extra{} $c[i]$ = number of red points at positions $\ge i$ (the suffix sum on the red marks); \texttt{c[i + 2]} leaves at least one element in the middle.
\hlp{Pitfall: with \mbox{$n=1$} (allowed by Codeforces) \texttt{a.len() - 2} underflows and the function panics} (\texttt{number\_of\_ways(\&[0])}); guard with
\texttt{if a.len() < 3 \{ return 0; \}}. Tested in \texttt{l10} against an $O(n^2)$ brute force.

\section{Fenwick tree (Binary Indexed Tree)}
\textbf{Problem: dynamic prefix sums.} Given $A[1,n]$, support
$\textsf{Sum}(i)=\sum_{k=1}^{i}A[k]$ and $\textsf{Add}(i,v)$: $A[i]\mathrel{+}=v$ (and $\textsf{RangeSum}(i,j)=\textsf{Sum}(j)-\textsf{Sum}(i-1)$).

\noindent\textbf{Trivial solutions.}
\begin{itemize}[nosep]
\item Store $A$: \hlp{\textsf{Sum} \mbox{$\Theta(n)$}}, \textsf{Add} $O(1)$.
\item Store the prefix sums: \textsf{Sum} $O(1)$, \hlp{\textsf{Add} \mbox{$O(n)$}} (all the following prefix sums change).
\end{itemize}
\hlb{The BIT supports both in \mbox{$\Theta(\log n)$} time.}

\subsection{Construction (from your notes)}
Example: $A=[3,2,-1,5,7,-3,2,1]$, $n=8$.
\begin{enumerate}[nosep]
\item \textbf{Relaxed problem}: answer $\textsf{Sum}(i)$ only when $i$ is a power of 2 (and \textsf{Add} for any $i$). Store only those prefix sums: $[3,5,\cdot,9,\cdot,\cdot,\cdot,16]$.
      \textsf{Sum} $O(1)$, \textsf{Add} $\Theta(\log n)$ (only $\log n$ stored values can change).
\item Add a \hly{fake root at position 0} (value $0$) and link to it the stored nodes, which cover the ranges $[1,1],[1,2],[1,4],[1,8]$: positions $0001,0010,0100,1000$ in binary,
      \hlb{exactly one bit set}.
\item \hly{Cover the uncovered parts by applying the same principle recursively.} Between $4$ and $8$ the uncovered part is $[7,-3,2]$ (positions $5,6,7$, i.e.\ $1,2,3$ shifted by $4$):
      its relaxed solution stores $[5,5]=7$ and $[5,6]=4$, positions $0101$ and $0110$ (\hlb{two bits set}), children of node $4$. Then $[-1]$ at position $3=0011$, range $[3,3]$,
      child of node $2$; and $2$ at position $7=0111$ \extra.
\item Observation in your notes: \hlb{the number of trailing 0s in the binary representation of a node = number of its children.}
\end{enumerate}
\textbf{Operations} (your notes stop here, running times not written):
\begin{itemize}[nosep]
\item $\textsf{Sum}(i)$: start from the node whose range ends at $i$ (node $i$) and sum its value and the values of its ancestors up to the root.
\item $\textsf{Add}(i,v)$: update the values of all the nodes whose range contains $i$.
\end{itemize}
\extra{} Node $i$ covers the range $(i-\text{lsb}(i),\,i]$, where $\text{lsb}(i)$ is the lowest set bit of $i$. The parent of $i$ is $i-\text{lsb}(i)$ (clear the lowest set bit),
so \textsf{Sum} visits at most $\log n+1$ nodes; \textsf{Add} visits $i,\ i+\text{lsb}(i),\dots$ (the ``next sibling'' in the blog), again $O(\log n)$ nodes.
For the example: the array is $[0\,|\,3,5,-1,9,7,4,2,16]$; $\textsf{Sum}(7)=T[7]+T[6]+T[4]=2+4+9=15$.

\noindent\textbf{Prof's code} [blog] (verbatim):
\begin{lstlisting}
#[derive(Debug)]
pub struct FenwickTree {
    tree: Vec<i64>,
}

impl FenwickTree {
    pub fn with_len(n: usize) -> Self {
        Self {
            tree: vec![0; n + 1],
        }
    }

    pub fn len(&self) -> usize {
        self.tree.len() - 1
    }

    /// Indexing is 0-based, even if internally we use 1-based indexing
    pub fn add(&mut self, i: usize, delta: i64) {
        let mut i = i + 1;
        assert!(i < self.tree.len());

        while i < self.tree.len() {
            self.tree[i] += delta;
            i = Self::next_sibling(i);
        }
    }

    /// Indexing is 0-based, even if internally we use 1-based indexing
    pub fn sum(&self, i: usize) -> i64 {
        let mut i = i + 1;

        assert!(i < self.tree.len());
        let mut sum = 0;
        while i != 0 {
            sum += self.tree[i];
            i = Self::parent(i);
        }

        sum
    }

    pub fn range_sum(&self, l: usize, r: usize) -> i64 {
        self.sum(r) - if l == 0 { 0 } else { self.sum(l - 1) }
    }

    fn isolate_trailing_one(i: usize) -> usize {
        if i == 0 {
            0
        } else {
            1 << i.trailing_zeros()
        }
    }

    fn parent(i: usize) -> usize {
        i - Self::isolate_trailing_one(i)
    }

    fn next_sibling(i: usize) -> usize {
        i + Self::isolate_trailing_one(i)
    }
}
\end{lstlisting}
\noindent\extra{} Tested in \texttt{l10::fenwick}: on the example (internal array $[0,3,5,-1,9,7,4,2,16]$) and against the trivial array on random add/sum sequences.
